以下是你在安装或运行 Tram 时可能遇到的最常见问题的解决方案。请查看相关部分以快速解决你的问题。

## 先检查这些状态命令

在排查前，先确认当前状态没有已经显而易见的问题：

- `tram auth status`
- `tram mcp list`
- `tram extensions list`
- `tram channel status`
- `/arena status`

这些命令可以帮你快速判断问题是出在认证、扩展、MCP、通道，还是 Arena 会话本身。

<AccordionGroup>
  <Accordion title='"tram: command not found"'>
    此错误表示 npm 安装全局二进制文件的目录未包含在系统的 `PATH` 中。运行 `npm install -g @tram-ai/tram@latest` 后，你的 shell 无法找到 `tram` 可执行文件。

    **查找 npm 全局 bin 目录：**

    ```bash
    npm bin -g
    ```

    然后将该目录添加到你的 `PATH`。

    **macOS 和 Linux：**

    将以下行添加到你的 shell 配置文件（`~/.bashrc`、`~/.zshrc` 或等效文件），将路径替换为上述命令的输出：

    ```bash
    export PATH="$PATH:$(npm bin -g)"
    ```

    重新加载你的 shell 配置文件：

    ```bash
    source ~/.zshrc
    ```

    **Windows：**

    打开**系统属性** > **环境变量**，将 npm 全局 bin 路径（通常为 `%APPDATA%\npm`）添加到你的 `Path` 变量中。然后重启终端。
  </Accordion>

  <Accordion title="Node.js 版本错误">
    Tram 需要 Node.js 20 或更高版本。如果你看到有关不支持的 Node.js 版本的错误，请检查已安装的版本：

    ```bash
    node --version
    ```

    如果输出低于 `v20.0.0`，请使用以下方法之一升级 Node.js：

    **使用 nvm（推荐）：**

    ```bash
    nvm install 20
    nvm use 20
    ```

    **直接安装：**

    从 [nodejs.org](https://nodejs.org/) 下载并安装最新的 LTS 版本。

    升级后，确认版本并重新安装 Tram：

    ```bash
    node --version
    npm install -g @tram-ai/tram@latest
    ```
  </Accordion>

  <Accordion title="身份验证错误 / API 密钥被拒绝">
    如果 Tram 报告身份验证错误或提示你的 API 密钥无效，则你在设置期间提供的密钥可能不正确、已过期或权限不足。

    修复方法：

    1. 登录你的 AI 模型提供商仪表板，验证 API 密钥处于活动状态且未过期。
    2. 准确复制密钥，避免尾随空格或缺少字符。
    3. 重新运行认证向导：

    ```bash
    tram auth
    ```

    如果你用的是 Coding Plan，可以直接重新执行：

    ```bash
    tram auth coding-plan
    ```

    按照提示输入更正后的 API 密钥。
  </Accordion>

  <Accordion title="Tram 挂起或无响应">
    如果 Tram 启动后似乎冻结或从未返回响应，请按以下步骤排查：

    1. **检查网络连接** — Tram 必须能够通过网络访问模型提供商的 API。
    2. **检查提供商的状态页面** — 你的模型提供商可能正在经历故障或性能下降。
    3. **中断并重启** — 按 `Ctrl+C` 停止当前会话，然后重新运行 `tram`。

    ```bash
    tram
    ```

    如果问题持续存在，尝试切换到其他模型提供商，以确定问题是否特定于某个提供商。
  </Accordion>

  <Accordion title="安装时权限错误">
    如果在运行 `npm install -g @tram-ai/tram@latest` 时看到权限错误，请不要使用 `sudo` 重新运行该命令。在 npm 中使用 `sudo` 可能导致难以恢复的文件所有权问题。

    请使用以下方法之一修复 npm 权限：

    **方法 1 — 使用 nvm（推荐）：**

    安装 nvm 并使用它管理 Node.js 安装。nvm 将 Node.js 和 npm 安装在你的主目录中，因此全局安装永远不需要提升权限。

    **方法 2 — 更改 npm 全局目录：**

    将 npm 配置为使用主文件夹中的目录：

    ```bash
    mkdir -p ~/.npm-global
    npm config set prefix '~/.npm-global'
    export PATH="$PATH:$HOME/.npm-global/bin"
    ```

    将 `export` 行添加到你的 shell 配置文件以使其跨会话持久化，然后重试安装。
  </Accordion>

  <Accordion title="响应缓慢">
    响应速度主要取决于你的模型提供商和所选模型。如果响应感觉缓慢，请考虑以下因素：

    - **切换到更快的模型** — 较大的模型生成响应需要更长时间。对于日常查询，尝试提供商提供的较小或更快的模型变体。
    - **检查网络延迟** — 缓慢或不稳定的连接会增加到提供商 API 的往返时间。
    - **检查提供商负载** — 一些提供商的响应时间会因需求而变化。如果缓慢持续，请查阅提供商的状态页面。

    要更改模型，可以直接在会话里切换：

    ```bash
    /model
    ```

    如果你想把更快的模型单独保留给提示建议，可以用：

    ```bash
    /model --fast <model>
    ```
  </Accordion>
</AccordionGroup>
