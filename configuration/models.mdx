模型选择是 Tram 最重要的用户控制项之一。你可以通过设置文件、交互命令和 Arena 的参数来决定 Tram 在不同任务里使用哪个模型。

## 你可以控制哪些模型相关项

主模型由 `model.name` 决定。你在交互会话中也可以使用 `/model` 直接切换当前会话的模型。

```bash
/model
/model --fast qwen3-coder-flash
```

`/model --fast` 用来设置“快速模型”，它会优先用于提示补全、建议生成和其他低延迟场景。你如果只输入 `/model --fast`，Tram 会打开快速模型选择对话框。

除了主模型外，你还可以控制：

- `fastModel`：用于建议和快速响应的轻量模型。
- `model.fallbacks`：主模型失败时的备用顺序。
- `model.maxSessionTurns`：单个会话最多保留多少轮。
- `model.sessionTokenLimit`：会话 token 上限。
- `model.chatCompression`：压缩历史对话的策略。
- `model.skipStartupContext`：是否跳过启动时的上下文注入。
- `model.generationConfig.timeout`、`maxRetries`、`schemaCompliance`、`contextWindowSize`：请求与工具 schema 的生成细节。

## 认证类型和模型提供商

Tram 的模型配置和认证是联动的。`security.auth.selectedType` 决定当前使用哪种认证类型，`security.auth.apiKey` 和 `security.auth.baseUrl` 则决定具体怎么连到提供商。

如果你在同一套 Tram 里接了多个提供商，`modelProviders` 会把不同 `authType` 下的模型分组保存。这样你就能在不同提供商之间切换，而不用重建整套配置。

## 任务类型和模型选择

不同任务适合不同模型：

1. **大型代码库探索**：优先选上下文窗口更大的模型。
2. **单文件修改和快速问答**：优先选响应更快、成本更低的模型。
3. **脚本化自动化**：优先选稳定性更高的模型，并考虑配置 `output.format` 为 `json`。

## Arena 中的模型写法

如果你使用 Arena，模型列表可以写成 `authType:modelId`。例如：

```text
/arena start --models openai:gpt-4o,anthropic:claude-3 "implement sorting"
```

如果你不写 `authType`，Arena 会使用当前会话的默认认证类型。

<Tip>
  如果你经常在“探索代码”和“执行具体修改”之间切换，可以把一个大上下文模型作为主模型，把一个更快的模型放进 `fastModel`。
</Tip>

<Note>
  模型越大，不代表越适合所有任务。对于脚本化或重复性任务，低延迟和低成本通常比绝对能力更重要。
</Note>
