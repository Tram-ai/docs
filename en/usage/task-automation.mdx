Tram can handle repetitive development tasks — from writing boilerplate to refactoring existing code — so you can focus on the work that matters. You stay in control: Tram generates suggestions, and you decide what to apply.

## Common automation prompts

**Write unit tests for a function:**
```
Write unit tests for the `parseConfig` function in src/config.ts
```

**Generate TypeScript types from a JSON schema:**
```
Generate TypeScript types for the JSON schema in schemas/user.json
```

**Refactor a function to use async/await:**
```
Refactor the `fetchUserData` function in src/api.ts to use async/await instead of promise chains
```

**Write a README for a module:**
```
Write a README for the src/utils/ directory that documents each exported function
```

**Convert a class component to a functional component:**
```
Convert the `ProfileCard` class component in src/components/ProfileCard.tsx to a functional component using hooks
```

## Using headless mode for scriptable tasks

For tasks you run regularly, headless mode lets you bake Tram into your existing workflow. Pass your prompt with the `-p` flag and pipe or redirect the output wherever you need it:

```bash
tram -p "Write unit tests for src/utils/format.ts" > src/utils/format.test.ts
```

<Tip>
  Combine headless mode with shell pipes and output redirection to integrate Tram into existing scripts. For example, you can generate a file, append to a log, or feed Tram's output directly into another command.
</Tip>

## Review output before applying

Tram generates suggestions based on what it can read from your codebase. The output is a starting point, not a finished product. Read through what Tram produces, apply the parts that make sense, and adjust anything that doesn't fit your project's conventions.

<Warning>
  Always review AI-generated code before committing it. Tram can produce plausible-looking code that contains logic errors or doesn't account for edge cases specific to your project. Treat its output the same way you'd treat a code review suggestion: consider it, don't just accept it.
</Warning>
